## Q1. E0 — verdict: ACCEPT WITH CORRECTIONS

**Shoup vs Maurer.**
- Shoup 1997 (Eurocrypt, "Lower bounds for discrete logarithms and related problems"): group of order n, random injective
  encoding sigma: Z_n -> S, |S| >= n; the algorithm receives labels (strings) and a group-operation oracle (add/negate on labels). Only
  oracle calls are charged; everything else (bit access, integer order of labels, sorting, hashing, equality, unbounded local
  computation) is free. Bound (memory): any such algorithm making m oracle calls solves DL with probability O(m^2/p), p the largest
  prime factor of n, probability over sigma, the secret and coins. So the answer to "are order and bit access free in Shoup's model" is
  **yes**; they are free *and useless*, because sigma is independent of the group structure, so every function of the labels
  other than equality patterns (collisions) is independent of the secret. The proof bounds the probability of a collision not forced
  by the known linear relations.
- Maurer 2005 (IMA CC, "Abstract models of computation in cryptography"): opaque handles, operations only through an
  oracle (group op, equality test); no bit access at all; handle order reveals only creation order. Same Omega(sqrt p) for DL. Model is
  strictly more restrictive in what the algorithm may touch, so its bounds are formally for a weaker adversary.
- Jager–Schwenk (ProvSec 2008, "On the equivalence of generic group models", memory only): shows the two models give comparable
  hardness bounds for the standard problems; I did not retrieve it, and the precise class of problems / the exact reduction should be
  checked before citing.
- **What the bound covers:** algorithms that, for the unknown random sigma, are charged only for group-op queries; DL, CDH, and (with
  modifications) DDH; avg-case over sigma. For the curve x-coordinate encoding there is the x(kP)=x(-kP) quotient: the model needs
  the Z_r/+-1 variant (constant factor, Omega(sqrt r) unchanged).
- **What it does not cover:** (i) any fixed encoding: the theorem is about an average over sigma and says nothing about one concrete
  curve (Koblitz–Menezes, "Another look at generic groups", 2007; Dent 2002 and Fischlin 2000 show generic-model security is not
  implied for any instantiation; recalled, unretrieved); (ii) algorithms using field/ring structure of the label (index calculus in F_p^*,
  Weil/Tate pairings, MOV, anomalous-curve Smart attack, Weil descent); (iii) preprocessing/advice depending on sigma (Corrigan-Gibbs–Kogan
  Eurocrypt 2018, Coretti–Dodis–Guo Crypto 2018: S*T^2 = Omega~(r), recalled); (iv) quantum access; (v) the algorithm quantifier order:
  A is fixed before sigma, so for a fixed sigma0 a trivial algorithm with a hard-coded answer wins (the statement is about families).

**Needed corrections to E0 as written.**
1. "Shoup already allows order/bits" is correct but should say they are **free and informationless under random sigma**; in Maurer's
   model they are not available at all. Do not call E0 a property of "the generic group model" without naming Shoup's version.
2. "must contain a k-informative distinguisher between k -> x(kP) and a random injection". Formal version (Prop E0'): fix a family of
   curves (p_n), algorithm A making q = q(n) group-law oracle calls, success probability eps(n) on uniform Q. Let D(sigma) := run A, then
   verify the output k' by computing k'P with O(log r) oracle calls and comparing with Q. Shoup gives Pr_random[D=1] <= O((q+log r)^2/r),
   so D has advantage >= eps - O(q^2/r) between the real encoding and a random injection into the *same image set* X = {x(kP)}.
   This is a **theorem, but tautological**: D is A itself plus a verifier, "k-informative" is the success predicate. It adds no mechanism.
3. The converse and the loose reading are false/vacuous. Counterexample to "any distinguisher helps": a distinguisher between x-coords of
   the curve and a random injection into F_p exists trivially (Legendre symbol of x^3+ax+b; toy run: pass rate 1.000 real vs 0.463
   random, evidence file below) and carries exactly zero information about k, since it is symmetric under relabelling k. The injection
   must therefore be into the image set X, not into F_p (otherwise membership alone distinguishes), and "also yields information about
   k" must be formalised (e.g. a predicate with advantage correlated with k, or a hard-core-bit-style predicate). Informativeness is
   the entire content; the "distinguisher" language is a restatement of "non-generic algorithm".
4. Single-curve phrasing ("on a concrete curve beat sqrt r") is not meaningful asymptotically; state for a family, or state a
   concrete-security reading explicitly as heuristic.
5. The oracle in the real setting is implemented by explicit field formulas, so the non-generic information can come from the
   operation's representation as well as from the encoding; "encoding vs random injection" should read "(encoding, op implementation)
   vs (random encoding, black-box op)".
Classification: **Prop E0' is a (trivial) theorem; the slogan "any beater must contain a k-informative distinguisher" is a true
tautology; the strengthened reading "distinguisher of a natural/low-complexity kind, independent of the solver" is a heuristic with no
support, and in general false as a characterisation** (distinguishers without k-information exist; and a k-informative predicate with
small advantage need not yield a faster DL algorithm without an amplification/search-to-decision argument).

## Q2. E3 — verdict: ACCEPT WITH CORRECTIONS (as stated), and clarify scope

**Which model does the repository use?** Equality branching only. DecisionTree.lean: `Tree` = `leaf | arith op next | test reg ifZero
ifNonzero`; test is "register = 0"; `Tree.run` branches on `acc.getD reg 0 = 0`; the file header says "Nothing here concerns
comparisons, bit extraction or bit complexity". HYP-dbe79a50 text says "branching only on register = 0?" and "Comparisons ... remain
outside the model". Constants: `Op.const c` is an arithmetic node and is **counted** by `arithDepth` (HYP notes confirm). Only register 0
(the input) is free.

**Does E3 apply to it?** Not as stated. E3(i) is a correct observation about a *different* model:
- Order comparisons "g(u) < c" against constants: a BST over the sorted values x(1..N)P has N leaves, depth ceil(log2 N) and 0
  arithmetic nodes. Toy confirmation (r=4923, N=300): correct on all inputs, depth 9 = ceil(log2 300), arithmetic nodes 0.
  So arithmetic length is vacuous in the comparison model, and also in an equality model if "u = c?" is a primitive free test.
- In the *formal* equality model, a table lookup costs a const and a sub per test (a test needs a register that is zero iff u = c);
  the chain tree for k has ~2k arithmetic nodes on its path, so max L = 2N for N inputs, nowhere near the DT bound's weak requirement
  L >= log2((N+1)/9). So the formal Theorem DT is not contradicted, and E3 (i) does not attack it. The vacuity arises only if one
  (a) allows order tests or (b) makes constant-comparison tests free, because then equality chains reach leaves at zero charged cost.
- The cost that remains is **size/depth**: any tree on N distinct outputs has >= N leaves (trivial). Natural correct statement: a
  *size-depth* tradeoff, not a length bound. For the order-comparison model: (size S = number of constants/leaves, depth T) with S >= N and
  T >= log2 N, simultaneously achieved by the BST. The generic-with-preprocessing shape S*T^2 ~ r (Corrigan-Gibbs–Kogan; Coretti–Dodis–Guo,
  recalled, unretrieved) is a statement about *generic* algorithms with advice, not about comparison trees; E3's remark "matches the
  S*T^2 >= N shape (S=N, T=log N)" is an analogy and should be marked as such, not a derived tradeoff. I do not claim to have a
  proven S,T lower bound for comparison trees; for comparison trees over an input of n = log p bits with N = r-ish values, unconditional
  circuit/branching-program lower bounds beyond what is known would be required for polylog-size programs (agree with E3(ii)).
- Also the uniformity gap: a BST over N values is an N-sized non-uniform advice table; "arithmetic length" is the only resource Theorem DT
  controls, which E3 correctly flags.
- Cost caveat: with real-RAM comparisons, each constant has O(log p) bits, so size accounting should be in bits, S_bits = N log p.

Does the formal DT theorem extend if constants are free (folded into ops, equality-only)? Plausible (registers would still have degree
<= 2^t) but **not checked here**; the Lean model charges them, so any statement should say "constants are charged".

## Q3. Recommended phrasing for the barrier map (one paragraph)
"Theorem DT is a barrier for equality-branching algebraic computation trees in which constants and arithmetic operations are charged:
arithmetic depth L forces N <= 9*2^L - 1 independently of the number of equality tests; it says nothing about order comparisons,
bit access, or free constant tests. With order comparisons (or free equality-with-constant tests) a binary search over the sorted values
x(kP) solves DLP on N values with zero arithmetic nodes and depth ceil(log2 N), so arithmetic length alone is vacuous there and only a
size/depth (or bit-size) accounting is meaningful; any N-output tree has at least N leaves. In Shoup's generic model, bit access
and label order are free but uninformative, since the encoding is uniformly random and independent of the group; the Omega(sqrt r)
bound is an average over random encodings and applies to families, not to a fixed curve, and does not cover field-structure attacks,
sigma-dependent advice or quantum algorithms. Consequently, an algorithm beating sqrt r on the real encoding is, trivially, a
distinguisher against random encodings into the same image set (Prop E0', a theorem but a tautology); this is a restatement of
non-genericity, not a mechanism or a lower bound, and the informal phrase 'k-informative distinguisher' should be kept as a heuristic
organising principle only. Literature citations (Shoup 1997, Maurer 2005, Jager–Schwenk 2008, Corrigan-Gibbs–Kogan 2018, Coretti–Dodis–Guo
2018, Dent 2002, Koblitz–Menezes 2007) were not retrieved in this review."
