(1) Coordinate-defined sets (x/y windows, joint boxes, bit patterns, Hamming weight, order statistics, arithmetic progressions of x, x*y): m=3 closure ratio = 1.00 +- 0.02 for every family and size; m=2 closure ratio flat in p (slope of log2 ratio per bit CI contains 0 for all families) except **y-windows and linear-form windows, which carry a constant excess factor ~1.4** (E1) that, at the sizing s = 2.5 p^{1/3}, is a **GROWING ratio (slope 0.29 [0.27, 0.32] log2 per bit, 4.9 to 26 over 14 to 22 bits)** (E4, post-hoc). (2) That excess is **not usable**: fibres are disjoint, so the relation matrix is block diagonal with rank 0.17-0.19 s (measured, at every size) while solving for the logs needs rank s-1 (criterion U4). The residual (non-fibre) closure is exactly the random value (0.5-1.8, mean ~1).
(3) Images of short vectors (a,b) -> aG1 + bG2 have a huge, growing closure ratio (52 -> 520 over 14 -> 20 bits) but it is 99.5-100% trivial (coefficient vectors add in Z^d), the target coverage |V+V|/N collapses to 1-13% of the random value (0.9% at 20 bits), and membership needs a DLP. The wrap-around (informative) closure is the random expectation, concentrated in rare events that are collisions.
(4) Local search (log space, O(N) preprocessing) finds sets with ratio 8 -> 25 that are arithmetic progressions in log space (90% of the dilated set in an arc of length 1.00 s vs 12-101 s for random sets) and look coordinate-uniform; their only short description is (start, difference), i.e. logs.

## 2. Item 1 — mechanism: what the candidates are and what they would have to do
To beat the supply bound a base needs closed relations among unknown logs that are (i) numerous (>= s-1 independent), (ii) log-free testable, and (iii) leave target coverage intact. I tested candidates by the three quantities above and added a fourth (post-hoc) after the finding in E1: U4, the rank/connectivity of the relation matrix over F_r.

Candidate 1 and 2 (E1, `g1_coord.py`; 11 families): rand (control); xwin; ywin (ybar = min(y, p-y) interval); box (x-interval x ybar-window); lowbits (joint low-bit pattern of x and ybar); popcount (smallest joint Hamming weight); xyl (window of alpha x + beta y, symmetrised); xap (x in an arithmetic progression of F_p with random ratio, an integer-vector image); xy (window of x*y); ordmin (local minima of ybar along x order, then an x-window of them); ordgap (x with the largest spacing to the next x in sorted order).
Candidate 3 (E2, `g2_lattice.py`): V = {sum a_i G_i, |a_i| <= B}, d = 2, 3, known G_i; closure split into trivial (coefficient vectors add in Z^d) and nontrivial (wrap-around mod N).
Candidate 4 (E3, `g3_search.py`): annealed hill-climbing of tri in log space (s = 2 sqrt N), then tests of the found set.
Candidate 5, anything else (E4, post-hoc, `g4_fibre.py`): fibre closure. A window of a function f of degree deg f in (x,y) is a union of whole fibres; each fibre meets E in 3 deg f points summing to O (Abel). ywin is f = y (horizontal lines, 3 points), `lin` is f = y - alpha x (lines of slope alpha, V not negation closed). This is free zero-sum closure of length 3 deg f that does not depend on any luck.

## 3. Item 2 — pseudocode and prototype
```
closure_ratio(V):          # g1_coord.stats / g2_lattice.classify / g4_fibre.analyse
  key = sorted(x*p+y over V)
  for each chunk of ordered pairs (u,v), u != v:       # vectorised affine addition, s^2 group additions
      w = u+v;  tri += [w in V]                        # membership by hash/sort, or by the predicate itself for coordinate families
      sums.append(key(w)) for u<v
  quad = sum C(r_t,2) over multiplicities r_t of the sums;  cov = #distinct sums / N
fibre_rank(V):             # g4_fibre.analyse
  relations = {sorted(u,v,t) : u+v+t = O, u,v,t in V};  unknowns = one per +-pair (l(-P) = -l(P))
  rank over GF(2^31-1) of the relation matrix, plus connected components of the relation hypergraph
```
Predicates tested without logs (U1 holds): `y_min in [y0, y0+h)` etc. are poly(log p) from the coordinates alone.
No end-to-end ECDLP solver was built (pre-registered rule: only for GROWTH and USABLE). The index-calculus pipeline that would consume such a base is F's (RUN-7f3d67ad) and E's accounting; I did not re-run it.

## 4. Item 3 — correctness
Every counted closure is a group-law identity computed with the vectorised affine addition (`add_vec`, handles doubling and P + (-P) = O; `all_points` count agrees with the Legendre-sum order for every curve, assert in `g1_coord.py`). Random-control ratios are 0.975-1.005 (tri) and 0.98-1.00 (quad) and cov/cov_rand 1.00-1.007, which validates the normalisations. Expectation of the lattice nontrivial count over uniformly random lambda is exactly (number of vector triples with nonzero difference)/N because P[a + b lambda = 0 mod N] = 1/N for 0 < |b| < N. No probabilistic algorithm is proposed, so there is no success-probability claim.

## 5. Item 4 — complexity model
Cost of measuring one set: s^2 group additions. The question is the supply side of index calculus (finder cost is not charged to the candidate, which favours it):
- needed: s-1 independent relations among the s unknown logs (unknown count after l(-P) = -l(P) identification).
- random-like base, m=2: 2 s^3/(3N) closed triples, so s >= 1.22 sqrt N (E).
- fibre base (E4, `lin` family, s = 2.5 p^{1/3}): rank_fibre ~ 0.175 s measured at 4-5 sizes (13/62, 20/97, 28/156, 46/248, 70/400: 0.21, 0.21, 0.18, 0.19, 0.175). The remaining ~0.82 s must come from random closure ~ s^3/(6N) (unordered zero-sum triples), which forces s >= ~2.2 sqrt N versus 2.45 sqrt N for a random set: **a constant factor ~0.9 on the supply floor, exponent unchanged (heuristic: assumes the random and fibre relations are independent; not measured end to end).**
- lattice base: nontrivial closure expectation = random value s^3/N, so s >= c sqrt N again; trivial closure adds rank 0 about the group.
Total cost therefore stays Theta(sqrt N); memory O(s).

## 7. Item 6 — exact obstacle
A. **Closure splits exactly into three parts.** (i) trivial: relations implied by Z-linearity of a construction (lattice images, AP/GAP sets): they hold in every group, so carry no information about the group or k; (ii) fibre/geometric: relations forced by a coordinate predicate through Abel's theorem (ywin, lin): real, log-free, linearly many (~ s/6 per 3-fibre), but supported on **disjoint blocks**: each point lies on one fibre, so rank <= s/(3 deg f), measured 0.17-0.19 s (lines are the best case; conic or higher-degree fibres have 3d >= 6 points per relation and lower rank); (iii) wrap-around/random: the only part that couples different points, equals the random value s^3/N in expectation (E2 exact identity, E1 control, quad cov all ~1.00).
B. **Index calculus needs s-1 independent connected relations. Fibre relations give <= 0.19 s and random relations give s^3/(6N) (m=2), so s >= ~2.2 sqrt N: constant improvement ~10% of the random floor, exponent 1/2 unchanged.** Making fibres connect requires V to be a union of fibres of two (or more) different pencils simultaneously; closure under a second pencil produces new points each with 2 new unknowns for 1 new relation (tree-like hypergraph, relations <= (unknowns-1)/2), cycles only arise by random collision (birthday, ~s^2/N) = the same supply bound. (This tree-likeness argument is heuristic; E4 shows the first step: components >= s/3.)
C. **Coverage versus energy.** High closure of the lattice/AP type equals large additive energy, hence small sumset (|V+V| ~ 4s versus s^2/2; measured cov ratio 0.9% at 20 bits), so a random target decomposes with probability ~ 4s/N instead of s^2/N: closure is bought with coverage. By Freiman/BSG-type structure (standard, not re-proved here) sets with closure ratio growing like N/s^2-or-more are dense in a generalised AP of rank d, whose description (start, differences) is a set of logs; in a prime-order group there are no subgroup cosets to use instead (isogeny kernels and CM endomorphisms act as scalars, E and F).
D. **Usability of images of Z^d.** Membership of an arbitrary point in {a G1 + b G2} is a 2-D DLP unless a table of all s points is stored (O(s) memory, hash lookup O(1) -- which is available for any set, so it is not a test of structure). The wrap-around identity between vector (a,b) and (a',b') is a collision aP + bQ = a'P + b'Q: collision cost ~ sqrt N, the box-BSGS/rho birthday.
E. **Searching for sets** is itself a DLP-hard task in this problem: E3's local search runs in log space and costs O(N) preprocessing; log-free hill climbing needs a collision to make any progress (a new point improves closure only if it equals a sum of two present points).

## Limitations
Toy sizes (p < 2^22; E4 22 bits has 3 curves; E1 main stops at 20 bits because the 22-bit runs were aborted under CPU contention), small numbers of curves (3), Python/numpy; the machine was shared with other runs, so wall-clock times mean nothing and none were used. E1 over-dispersion: ratios of single windows vary by +-30-50% (E1 many), so single-family differences of 5-10% (e.g. box 1.04-1.10) are not significant; the family slopes use per-size means of 9 windows. The fibre argument was found post hoc (labelled) and the "connectivity" criterion U4 was added after seeing the data; the 0.9 supply-floor factor is a heuristic estimate, not an end-to-end measurement. Lattice nontrivial mean is undersampled (6 events). E3 at 16 bits unconverged; its KS(x) excess at small N unexplained. Not tested: curves of composite order, multi-pencil closure, higher-degree functions (conic/cubic fibres: rank argument only), ECDLP-specific algebraic structure beyond coordinates, Weil restriction, e-to-the-structured bases from CM curves (E's analysis only), and no external literature was retrieved. The statement "no efficiently describable base exists" is therefore **not** proved: it is supported for the 11 coordinate families, lattice images, annealed search and line fibres above.
