## Candidate A1 — Farey-height factor base, meet-in-the-middle index calculus (l=2: 4-term, l=3: 6-term; m=3 control)
1. Mechanism. Factor base S_H = points with x = u/v mod p, |u|,|v| <= H (membership testable table-free by 2-dim Gauss
   reduction/continued fractions of x mod p, O(log p) field ops, O(1) memory; the prototype uses a hash set).
   Relations sum_i eps_i R_i = 0 among S_H come from collisions x(sum of l signed factor-base points) between two l-sums
   (generalised birthday on x), and targets R=aP+bQ matched to an l-sum give a + b k = sum eps_i log R_i. Linear algebra
   mod r yields log R_i and k.
2. Pseudocode: (a) enumerate Farey fractions by height until s points; (b) build table T of all signed l-sums
   (l=2: P_i+-P_j; l=3: (P_i+-P_j)+-P_k, i<j<k), sorted by x; (c) every x-collision with equal/opposite y gives one
   homogeneous row; (d) draw random aP+bQ (sums of 48-batches of precomputed random combos), look up x in T, each hit
   gives a row with rhs a and coefficient -b on k; (e) prune singleton columns, Gaussian elimination mod r with k
   last column, k determined iff an echelon row has only the k column; (f) if undetermined s <- 1.25 s+1 (all ops
   counted). Prototype `a1_farey_ic.py` (numpy-vectorised batch addition; ops counted per addition). Recovers k:
   66/66 correct for l=2 and l=3, 50/50 for m=3 (b<=20).
3. Correctness. Each row is a true identity in E(F_p) (rows are formed only when y agrees up to sign), so the true
   (log vector, k) solves the system; the output is checked kP=Q, so any output is correct; failure only by rank
   deficiency (retry). Success probability measured 100% (with up to 8 attempts; mean attempts 1.8 (l=2), 2.2 (l=3)).
4. Complexity model. s unknown logs; table size T ~ (2s)^l/l!; collisions ~ T^2/p. Need ~s rows => T ~ sqrt(p s) group
   additions (build) + target phase ~ s p/(2T) additions; with s ~ p^{1/(2l-1)}: U1 ~ p^{l/(2l-1)} (l=2: p^{2/3},
   l=3: p^{3/5}, m=3: p). Memory T. FB construction s*H*O(log p) field ops. Dense LA ~ s^3/3 mulmods (sparse: ~s^2).
   Key structural fact: U1 >= ~sqrt(p*s) > sqrt(p) always, because s unknown logs require s independent relations and
   each costs a birthday-collision; s cannot be < ~log p/log 3 (table needs ~sqrt(p s) sums). Measured
   U1/sqrt(p s) = 4-8 at 18-24 bits (analysis.txt).
5. Measured scaling vs rho (same instances; U1 = point additions, setup included for both):

6. Obstacle. Relation finding by hashing costs sqrt(p*s) additions, strictly more than sqrt(p) (a rho collision gives k
   directly with s=1). The integer structure only supplies a cheaply describable factor base; it does not make relations
   cheaper than a birthday search, because x(R1+R2) is not a function of small-height structure (no Wagner-type
   partial-zero constraint on x of a sum). To win one would need a relation finder with cost << sqrt(p*s), i.e. a
   non-generic solver (cf. Semaev/PKM at m>=3, already measured negative in this lab).

## Candidate A2 — Veronese-lattice (Coppersmith-style) decomposition of a target into two Farey points
1. Mechanism. S_3(x1,x2,x_R)=0 with x_i=u_i/v_i becomes a linear condition mod p on the 9-vector z=(u1^i v1^{2-i})(u2^j v2^{2-j})
   (rank-one Veronese tensor, entries <= H^4): z lies in a 9-dim lattice of determinant p. LLL on it, followed by testing all
   small combinations {-1,0,1}^9 of reduced vectors for rank-one Veronese form, would decompose R without table or scan.
2. Pseudocode/prototype `a2_veronese_lll.py`: build coefficient matrix c_ij of S_3 (checked against real point addition),
   basis of the lattice, own float-GS LLL (delta .99), enumerate 3^9-1 combos, test minors, recover x1,x2 mod p, verify
   x_i in factor base and S_3=0. Plugging a success into A1's target step would recover k; no success occurred at benchmark
   sizes, so no end-to-end k from A2 beyond the shared A1 pipeline (the 12-bit successes were decomposition-level only, not
   run end to end).
3. Correctness. A reported decomposition is verified algebraically (S_3=0, both x in factor base), so it is sound; the
   failure mode is only non-recovery.
4. Complexity model. If it worked: poly(log p) per target vs p/(2 s^2) random targets needed (existence probability ~ 2 s^2 / p);
   no preprocessing besides the factor-base table for verification. Lattice success needs the true vector (norm ~ H^4)
   below the lattice's generic short-vector scale ~ p^{1/9} (times LLL factor): H < p^{1/36}, whereas existence needs
   H^4 >~ p^{1/2}... (H^4/p ~ 1/s^2-scale), a gap of exponent ~ (1/3 - 1/9)+ in p.
5. Measured (sizes pre-registered 16/20/24 bits, 1 curve each; existence E by exhaustive pair-sum table, success S by LLL):
   16 bits: E=124/1500 targets, S=0; 20 bits: E=77/2500, S=0; 24 bits: E=61/4000, S=0 (false positives 0/20 each).
   Sweeps at 20 bits (not pre-registered, same code): factor-base factor 0.5: E=14, S=0; 2.0: E=187, S=0.
   Development run at 12 bits (not part of the decision): E=40/300 -> S=1 and E=60/400 -> S=2 (~2-3%): successes appear only
   when the true norm 2^9.3 is comparable to the lattice scale, i.e. at toy sizes where H^4 ~ p^{0.75}.
   Decision: S/E = 0 at 3 of 3 sizes => **A2 not viable** (pre-registered prediction).
6. Obstacle. The rank-one (Veronese) constraint is not a lattice condition; LLL only sees the linearised 9-dim lattice
   whose shortest vectors have size ~p^{1/9}, while actual solutions have size H^4 ~ p^{2/3} at the factor-base size where
   solutions exist. Classical Coppersmith small-root bounds need all solution coordinates far below p^{1/deg-monomials};
   existence threshold and lattice-recoverability threshold are separated by a polynomial factor in p.

## Candidate A3 — lift to E(Q) (Miller/xedni setting), small-coefficient curve y^2=x^3-2
1. Mechanism. If E has small integer coefficients, E(Q)->E(F_p) is a homomorphism; relations of E(Q) are relations mod p
   for free. Lift P,Q to rational points of small height, solve the dependency over Z, output k = m/n mod r.
2. Prototype `a3_mordell_lift.py`: exact rational multiples nG of the generator G=(3,5) with max(|num|,den) < 2^bits;
   table of reductions mod p; lookup of P and Q; k = m n^{-1} mod r. Recovers k on planted instances (both P=nG, Q=mG
   reductions with small n,m): 50/50 at each of 12/16/20/24 bits.
3. Correctness. Reduction is a group homomorphism, lifts verified by table equality; output checked kP=Q.
4. Complexity. Table size = number of E(Q) points of naive height <= p: n_max <= ~3 for 2^12..2^24 (heights grow ~ n^2);
   coverage of E(F_p) = 2 n_max / r. For rank rho the count is polylog(p)^{rho/2}, vs |E(F_p)| ~ p (Miller). Success
   probability on a random instance = coverage^2.
5. Measured: random-instance success 0/300 at every size (coverage 1.2e-3, 1.2e-4, 6.9e-6, 3.9e-7). No scaling fit made:
   an instance family with success probability -> 0 has no meaningful cost comparison to rho (rho cost does not grow
   with this vanishing coverage; effective cost = cost/coverage^2 is unbounded).
6. Obstacle. Rank/height: the image of small-height E(Q) in E(F_p) has polylogarithmic size; generic points have no
   small lift. Escaping it needs rank ~ log p / log log p with computable generators, or a way to find lifts of generic
   points (xedni: the JKSST analysis reports the odds of a suitable lift are prohibitively small). Also, even with
   lifts, a rank>=2 dependency needs the unknown logs of the generators (A1's s unknowns again).

## Most promising next step
The only lever left in this territory is a relation finder cheaper than a birthday search on a lifted factor base. The
cheapest decisive test: measure, for m=3 and m=4 Semaev relations on a Farey/PKM factor base, the actual exponent of a
Groebner/resultant solver per relation (not hash joins) at 2^16..2^24, i.e. whether per-relation cost drops below
p^{1/6} (m=3) / p^{1/3 - ...} (m=4); the lab's m=3 result says no, so a non-generic relation structure (isogeny/CM
orbit) is the remaining candidate. Cheap robustness follow-up: re-run A1 with sparse linear algebra and a fixed-batch
target phase to separate setup from asymptotics.

## Limitations

implementation (no fplll, no Coppersmith/Jochemsz-May full lattice; a larger/shifted lattice could shift the threshold by
a constant exponent but cannot remove the rank-one gap in this argument, which is a heuristic not a proof); A3 uses
one rank-1 curve; the model exponents l/(2l-1) are heuristic and only partly matched; "Miller's height argument" as an
argument about heights was not confirmed by my lookup (found only that Miller gave heuristic reasons index calculus does not
extend, and Silverman-Suzuki support); xedni was analysed only through its published abstract (odds prohibitively high),
not re-implemented. Reviews: none (self-produced; not independently reviewed).
