## S_3 / S_4 correctness (results_verify.json)

## Methods and analytic per-relation cost
n = number of x-values in V (|V| = 2n signed points), pi = Pr[random R in V+V+V].
- **M1 table** (implemented, measured): hash of x(P1+-P2) over all pairs (n(n+1)/2 paired ops, about 2.5 n^2 units); per attempt up to n paired ops (5 units each, early exit on hit). T = (cost per attempt)/pi <= 5n/pi; total = 2.5 n^2 + (n+10) T + 3 n^2 = Theta(n^2) = Theta(p^{2/3}) at n = p^{1/3}. T = Omega(n) per attempt because computing x(R+-P3) for each of n candidates is >= 1 mult each. Sub-sampling P3 (k < n lookups) scales cost and pi together: T unchanged.
- **M2 S_4 pair scan** (implemented, counted polynomial arithmetic; k=12,14 only): for every x1<=x2 in V_x, build q(x3)=S_4(x1,x2,x3,x(R)) (quartic, about 46 mults with the B-polynomials precomputed) and test for a root in V: (a) Horner at all n values: pairs x (46+4n) = about 2n^3 per attempt; (b) PKM only: gcd(q, X^h - g^h) with X^h mod q by square-and-multiply: pairs x O(log h) with constant roughly 100-150 units/pair measured here: O(n^2 log n) per attempt. Both are worse than M1 at all tested sizes (measured below).
- **M3 smarter elimination** (analytic only; no CAS, sympy absent, not implemented): eliminating x3, x2 from S_4(x1,.,.,x(R)) together with x_i^h = g^h gives a bivariate-then-univariate chain with degrees ~4h then ~16h^2 (all-three elimination), so any root/gcd stage costs >= its degree = Omega(h) per x1-slice and Omega(h^2) overall; per-x1 slicing costs n slices x Omega(h). Equivalently the ring F_p[x2,x3]/(x2^h-c,x3^h-c) has h^2 grid points and testing whether a 25-term S_4 slice vanishes anywhere has no known sub-h shortcut (I know of none; unverified). All these lower bounds exceed p^{1/6} = sqrt(n). Correction of the task note: for a fixed degree-4 q, X^h mod q costs O(deg^2 log h), not O(h deg); the Omega(h) bound applies after elimination raises the degree to Theta(h).
- **Structural bound independent of T**: with |V| = p^{1/3}, even T = O(1) leaves LA = 3|V|^2 = 3 p^{2/3} > sqrt(p) (for p > 729). In this model total < sqrt(p) at m=3 is impossible; PKM-style gains need m >= 5 (LA < sqrt(p) iff 2/m < 1/2 only for m > 4; recollection of the standard cost model, not checked against the paper).
- Floor: one paired step costs 5 units, so T >= 5 > p^{1/6} whenever p < 5^6 = 15625: the threshold is below one counted step at the smaller toy sizes, so this question cannot be resolved by constant-sensitive toy measurements at 2^12.

## Verdict
Decision rule (pre-registered): "T < p^{1/6} achieved" iff some method has T < p^{1/6} at every k >= 14 and a fitted T-exponent < 1/6. **Not met.** Best implemented method M1 has T/p^{1/6} = 10-32 (T about 54-320 vs 5-10), per-attempt cost exponent about 0.33, T exponent 0.22-0.30; best total cost 44-83 sqrt p (9-17x the rho model) and rising (exponent about 0.61). Structural reasons: (i) any method that enumerates candidates x3 pays >= 1 mult per candidate, so per-attempt cost >= |V| = p^{1/3} > p^{1/6}; (ii) algebraic elimination (S_4 with coset membership) raises degrees to Theta(h) or Theta(h^2) and root/gcd cost is >= degree; the measured pair-scan methods cost n^2 log n to 2n^3; (iii) even with T = O(1), LA = 3|V|^2 = p^{2/3} exceeds sqrt p, so m=3 with |V| = p^{1/3} cannot beat sqrt(p) in this cost model. PKM-style subgroup-coset bases are statistically indistinguishable from small-x and random bases (pi, T). The hypothesis HYP-db508348 claim (no (m,B) below sqrt p at toy sizes) is further supported at m=3 on the tested domain; status stays experimental.

## Limitations
Toy sizes (p <= 1.06e6), 4-5 buckets per fit, 2-4 curves each; exponents are crude and no asymptotics follow. Unit cost model with free hash lookups and w_I=1 (w_I=10 in JSON); rho and LA are analytic models. M3 is analytic only (no Groebner/CAS; no sympy); its degree bounds are my derivation, unreviewed. M2 only measured at k=12,14, 40 R x 2 curves; gcd-route crossover not measured. Primes were selected for smooth p-1 (could bias to special structure only if the method used it; none did). Methods not tested: large-prime variation, sieving, relation reuse across R, FFT over mu_h, and bases with m=4,5. The 'floor' remark (T >= 5) means p^{1/6} < 5 for p < 15625, so the sub-2^14 rows are uninformative for the threshold. No independent review of this run; self-reported model identity.
