## 2. Map: integer-structure algorithms and the lower bounds that apply to them

### 2.1 Known algorithms that use integer structure of coordinates (all are Θ(√·) )
| Algorithm | Integer structure used | Cost | Source status |
|---|---|---|---|
| Baby-step giant-step (Shanks) | sorting/hash-lookup of x(jP) labels | O(√r) time and space | classical; cited as Shanks71 in Stanford CS355 notes (title-level only) |
| Pollard rho / kangaroo (lambda) | pseudo-random partition by low bits/size of x; interval version width N costs O(√N) | O(√r) / O(√N) | Pollard 1978 (title-level only; unverified recollection of exact bounds) |
| Distinguished points / parallel collision search | "easily testable property" = leading/trailing bits of the integer x; stores only DPs | near-linear speedup in #processors, still O(√r) total work | van Oorschot–Wiener, J. Cryptology 1999 (verified at abstract/search-result level) |
| Pollard–Strassen / BSGS with polynomial evaluation | none beyond arithmetic | closed (STATUS) | — |
| Preprocessing (Hellman/Mihalcik-style tables) | hashing of encodings | S·T² ≈ N | see 2.2 |
Observation (own, trivial): every one of these uses the integer structure only as an *implementation device for equality testing /
pseudo-random partition*; none uses a k-dependent regularity of the integers.

### 2.2 Which lower bounds apply, in which model
1. **Shoup / Nechaev / Maurer generic-group bound, Ω(√r)** (Shoup, EUROCRYPT'97, LNCS 1233, pp. 256–266: no generic DL algorithm beats
   ~√(largest prime factor of the group order); verified at review/search-result level). Model (verified at secondary level): the group
   is accessed through a *random injective encoding* σ: G → Σ.
   **Answer to "does allowing ORDER on encodings change the generic bound?" — No, and the reason is structural (own derivation,
   proof sketch, UNREVIEWED):** in Shoup's model σ is a uniformly random injection into bit strings and the algorithm may perform
   *arbitrary* computation on the strings it receives (sorting, bit extraction, order, factoring the label-as-integer); the bound
   counts only group-oracle queries (q) and gives success ≤ O(q²/r). Order/bits of random labels are therefore already allowed;
   conditioned on the equality pattern, the relative order of distinct random labels is uniformly random and independent of k, so a
   simulator answers comparisons for free. (Maurer's abstract model, equality only, is a restriction, not the one that matters.)
   Consequence: BSGS, rho, kangaroo, DP *are* inside the model and are optimal in it; "what exactly prevents doing better" is
   **the birthday/collision argument over random labels**: before the first label coincidence the transcript is independent of k.
2. **Preprocessing:** generic algorithms with S bits of advice and online time T need S·T² = Ω(εN) (Corrigan-Gibbs–Kogan, EUROCRYPT 2018;
   verified at abstract level; tight up to logs). A full sorted table of x(kP) (S ≈ r log r, T = O(log r)) is consistent with it.
3. **Comparison/branching-program time–space lower bounds** (Borodin–Cook / Yao; Beame et al.): sorting needs T·S = Ω(n²) on comparison
   branching programs; element distinctness T·S ≈ n^{2−o(1)} (Yao) vs Õ(n^{3/2}/S^{1/2}) for randomized multiway BPs (verified at
   search-result level; the secondary source was garbled on the exponent, check before use). These are bounds for *sorting/collision* as
   a function of n inputs; they say nothing about ECDLP, whose inputs are one point. Using them for ECDLP would need an explicit reduction
   from a hard comparison problem to DL; none is known (own remark, not a literature claim).
4. **Our own algebraic barriers** (B4/B5, Theorem DT HYP-dbe79a50: N ≤ 9·2^L − 1 for equality-branching trees, paper proof) are
   silent on order comparisons.
5. **Hard-core-bit results** (Boneh–Venkatesan CRYPTO'96 HNP over F_p; Boneh–Shparlinski CRYPTO'01: predicting LSB of x or y of abP from
   (E,G,aG,bG) ⇒ computing ECDH; Jetchev–Venkatesan CRYPTO'08: LSBs of ECDH secrets hard-core, reported (Shani, PKC'17) to rely on GRH).
   Direction of implication: *bit-predictor ⇒ DH solver*. They constrain algorithms that have a **DH oracle** (they are security
   reductions). A DL algorithm has no DH oracle, so these theorems impose **no lower bound on bit-access DL algorithms**; they are
   only consistent with (not evidence for) the pseudorandomness that E1/E2/E6 below probe.
6. **No unconditional bound in the unrestricted integer-structure model exists** beyond generic circuit-size lower bounds (own
   statement; any super-linear bound for an explicit DL circuit family would be a major circuit-complexity result). In that model the
   barrier is only the *absence of a mechanism*, i.e. observed pseudorandomness of x(kP) relative to the group structure.

**Main structural conclusion (E0).** An integer-structure algorithm beating √r must be non-generic: it must exploit that the real
encoding k ↦ x(kP) is not a random injection. Equivalently it must contain an efficient, **k-informative distinguisher** between
(x(kP))_k and a random injection. Tests E1/E2/E6 are such distinguishers of the most natural kinds (local order/bit/carry/difference
correlations; sorted-neighbour index structure; carry of conjugate roots).

## 3. Candidates

For each: property exploited; barrier escaped and why not already excluded; must be proved; kill condition; cheapest test; prior work.

**E1. Local integer correlation of x(Q) and x(Q+jP) (carry / bit / order / difference).**
Property: integer reps of neighbouring orbit points correlated (top bits, small differences, bit pairs). Escapes B9 only formally:
Weil-type bounds control additive-character sums, and the pair (Q, Q+P) lies on a curve in E×E, so a bound of order √p·polylog on
interval-product correlations is expected (UNVERIFIED recollection; Kohel–Shparlinski 2000 is verified only at abstract level) —
the test checks it empirically for non-interval predicates (bit pairs, difference histogram). Prove: nothing; a detected correlation
would be the entire result. Kill: no cell detected in both seeds. Test: E1 below (4 shifts × 4 statistics). Prior: none directly.

**E2. Sorted-neighbour index-difference leak ("sorting network"/closest-pair locator).**
Property: if integer-adjacent x-values had index differences concentrated on a set D, sorting a window of x(Q+jP) values plus one
comparison would reveal k modulo that structure. Escapes B1 (non-generic) and B4/B5 (order). Kill: no concentration beyond null.
Test: E2 below. Prior: none; relation to BSGS: BSGS uses sorted *tables* to match equal values, E2 asks for statistical near-equality.

**E3. Comparison-augmented algebraic decision trees (extension of Theorem DT / B5).** Theory only.
Findings (own, unreviewed): (i) with comparisons "g(u) < c" against *free constants*, a balanced binary search over the sorted values
x(1·P)…x(N·P) outputs k with L = 0 arithmetic nodes and depth ⌈log₂ N⌉: the arithmetic-length measure of Theorem DT is vacuous in
the comparison model unless tree **size** (number of distinct constants / leaves) is charged. Any tree with N distinct outputs has ≥ N
leaves, so a size-S, depth-T accounting is natural and this matches the generic S·T² ≥ N shape (table: S=N, T=log N).
(ii) The meaningful open question is therefore **uniform small-description programs** (loops/registers, polylog size) with integer
ops — i.e. a general branching-program/RAM bound for an explicit function, for which no technique above O(n)-type bounds exists.
So a Theorem-DT analogue is *not provable by degree arguments* and probably not at all with current technology. Verdict: not testable
cheaply; reduces to E0. Kill: n/a (the model collapses).

**E4. HNP / hard-core-bit lattice route to DL.** Literature + derivation.
Property: Boneh–Venkatesan lattice recovers a hidden α from MSBs of α·t_i mod p, a *linear* relation with small error. Escape: bit
access + lattice. Kill (derivation): (a) the EC analogue needs bits of x([αt_i]P) for known multipliers t_i — a DH-type oracle that the
DL solver lacks, since it only knows Q = αP; (b) x([αt]P) is not linear in αt mod r, so the lattice relation does not exist.
Boneh–Shparlinski/Jetchev–Venkatesan reduce bit-prediction to DH, not to DL. Status: KILLED by derivation + literature; not run.

**E5. Smoothness of lifted integer x (Miller / Silverman–Suzuki height obstruction), quantified.**
Property: lift to E(Q), size function = canonical height. Heuristic count: #{P ∈ E(Q), rank ρ, ĥ ≤ T} ~ T^{ρ/2}; to cover ~p residue
classes one needs T ≥ p^{2/ρ}; numerator ≈ T/ln 2 bits. Table (out_e5.txt; constants set to 1, heuristic): p = 2^256: ρ=1 → 2^512 bits;
ρ=2 → 2^256; ρ=10 → 2^51.7; ρ=18 → 2^29; **ρ=29 (record, Elkies–Klagsbrun; rank 29 under GRH, "at least 29" unconditionally) → ≈ 2^18.2 ≈ 3·10^5 bits** versus the
256-bit field. Even the record-rank curve gives lifts of ~10^5-bit integers for a 256-bit prime, before smoothness probabilities, and
the lift must *reduce to the given curve*: the coefficients are fixed mod p and the rank of a lift is not controllable (xedni's
failing; Silverman–Suzuki 1998: natural index calculus is worse than brute force — verified at abstract/search level). Status:
KILLED (literature + arithmetic). No sampling run.

**E6. Three-term carry predicate (new, from E1's "carries").** x(Q+P), x(Q−P) are the roots of a quadratic over F_p with coefficients
rational in u = x(Q). Their integer reps satisfy x_{k+1}+x_{k−1} = s(u) + c_k·p with c_k ∈ {0,1}. c_k is a poly-time computable
predicate of x(Q) (modular sqrt), depends on integer representatives, is even in k, has no obvious low Fourier complexity, and is outside
the Weil bound for rational functions. If c_k had a spectral line against characters of Z/r (or a global bias), it would give a bit of
information about k per query (as in C3). Kill: no line / bias in both seeds. Test: E6 below. Prior: none found.

## 7. Limitations

- Toy size only: p = 524309 (≈2^19), two curves, one prime. Weil-type error terms are relatively large at this size; structure that only
  appears at cryptographic sizes is invisible. Reduced n_null in E1 (60/20) lowers resolution; replication across two seeds is the only
  multiplicity guard; no Bonferroni formalism beyond that.
- E1/E2/E6 test specific statistics; absence of detection is not absence of structure. E2's X statistic detects a single repeated
  difference, not structured difference sets. Sensitivity floors were not measured (single planted strength each).
- Literature verification is at abstract/search-snippet level: Shoup's model (secondary), Boneh–Shparlinski/Jetchev–Venkatesan (abstract-level),
  Corrigan-Gibbs–Kogan (abstract-level), Miller/Silverman–Suzuki (secondary summaries), van Oorschot–Wiener, Elkies–Klagsbrun (Quanta/
  search), time–space bounds for comparison BPs (garbled secondary exponents). I did not find a source that explicitly treats "generic
  group with ordered labels"; the claim that order is free in Shoup's model is my own derivation from the model definition and is unreviewed.
  A Stanford lecture-notes PDF could not be parsed. The Kohel–Shparlinski bound and the expected Weil bound for (Q, Q+P) pair correlations
  are unverified recollection. Pollard kangaroo bound and Pollard 1978 are unverified recollection.
- E5 table is heuristic (T^{ρ/2} counting with constants 1; regulators, torsion, and the |E(Q)| point count asymptotics ignored); the rank-29
  curve is a single record, and the reduction of a lifted point to the target curve is not modelled.
- The DT/E3 discussion is a sketch; Theorem DT itself is a paper proof under review.
- Shared 4-core machine; timings are not benchmarks; no Lean, no review, no commit performed.
