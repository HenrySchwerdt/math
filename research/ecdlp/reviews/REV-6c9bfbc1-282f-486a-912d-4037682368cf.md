## Initial findings

(Written before reading the author assessment.)

F1. Build and trust base. The target builds at 9996995 under the pinned toolchain; both claimed
declarations use only the three standard axioms; no `sorry`/`admit`/`axiom`/`unsafe`/`native_decide`/
`implemented_by`/`decide` in the three files.

F2. Statement correspondence (curve form). `degree_bound_linear_short_weierstrass` assumes
`W.a₁ = W.a₂ = W.a₃ = 0` (so the affine equation is y² = x³ + a₄x + a₆, a = a₄, b = a₆), `(2:F) ≠ 0`
(char ≠ 2), `addOrderOf P = r`, `2N < r`, and `g.eval (xCoord (k • P)) = (k : F)` for `1 ≤ k ≤ N`;
the conclusion is `N ≤ 3 * g.natDegree + 2`. This matches Theorem C. Detailed checks:
- `(k : F)` is the image of k under ℕ → F, i.e. k mod char F; that is the only meaningful reading of
  "g(x(kP)) = k" in F, and the result holds for it (the proof uses only that the second difference
  (k+1) + (k−1) − 2k vanishes, true in any ring). Extension-field checks with N > p confirm this numerically.
- `xCoord` sends the point at infinity to the junk value 0. It is never evaluated at infinity in a
  way that matters: for 1 ≤ k ≤ N, k < r so kP ≠ 0 (`nsmul_ne_zero_of_lt`), and the relations use
  (k±1)P with 1 ≤ k−1 and k+1 ≤ N. Injectivity of k ↦ x(kP) on [1, N] is proved
  (`xCoord_smul_injOn`), not assumed.
- No nonsingularity/discriminant hypothesis on W is required; points of `W.Point` are nonsingular by
  construction. The Lean statement is therefore at least as general as Theorem C (it also covers the
  nonsingular points of singular short Weierstrass cubics).
- r = 0 (Mathlib's `addOrderOf` for infinite order): `2N < 0` is impossible, so the theorem says nothing
  about points of infinite order. Informally Theorem C with r = ∞ would also be true by the same proof.
  This is a scope restriction, not an error; it is irrelevant for finite fields (the ECDLP setting),
  where every point has finite order. The informal statement should say "P of finite order r".
- N = 0, 1, 2: conclusion trivially true (N ≤ 2 ≤ 3d + 2). For N ≥ 3 constant g is excluded since it
  would force 1 = 2 in F. g = 0 has natDegree 0 and is covered by the same branch.
- Docstring mismatch (cosmetic): the docstring of `degree_bound_linear_short_weierstrass` says
  "P of odd order r" but the statement requires no oddness. The statement is the more general one.

F3. Non-vacuity. Hypotheses are jointly satisfiable: for any P of order r ≥ 3 on a short Weierstrass
curve in odd characteristic and N with 2N < r, the nodes x(kP) are distinct, so a Lagrange interpolant
exists. Concrete instance in command 6 (F_7, r = 11, N = 4, deg g = 1). This instance is checked in
Python, not instantiated in Lean (see Limitations).

F4. Abstract-sequence form. `degree_bound_of_x_relations_linear` takes an arbitrary `xs : ℕ → K`, a free
`x₀`, injectivity on [1, m], and the cleared x-addition sum/product relations for 2 ≤ k ≤ m − 1; it does
not require xs 1 = x₀. This is a stronger (more general) algebraic statement; its hypotheses are
discharged in the curve form by `smul_relations`, which is derived from Mathlib's `Point.xRep_add_of_X_ne`/
`xRep_sub_of_X_ne` and the curve equation (no assumed curve facts).

F5. Proof structure. The argument is the expected one: for d = deg g ≥ 1, the polynomial
N0(u) = Σ gᵢ D^{d−i} qᵢ(u) − 2 D(u)^d g(u), with D = (u − x₀)² and qᵢ the cleared Newton power sums of the
roots of z² − (A/D) z + B/D, satisfies N0(x_k) = D(x_k)^d (g(x_{k+1}) + g(x_{k−1}) − 2 g(x_k)) = 0 for
2 ≤ k ≤ N − 1; the first sum has degree ≤ 2d and the second term exactly 3d (uses 2 ≠ 0 and D monic),
so N0 ≠ 0 of degree 3d with ≥ N − 2 distinct roots. All steps are explicit (`natDegree_sub_eq_right_of_
natDegree_lt`, `card_le_degree_of_subset_roots`, `Finset.card_image_of_injOn`). I found no suspicious
shortcut, no hypothesis that trivializes the goal, and no reliance on junk values. Note
D(x_k) ≠ 0 is not even needed for the vanishing argument (only for the curve-side relations, where
x(kP) ≠ x(P) is proved).

F6. Numerical check of the mathematical core: 12459 cases across prime and extension fields of odd
characteristic (including char 3 and wrap-around k mod p), 0 violations; the bound was never attained
with equality (minimal slack 1) in the sample, so tightness is not established (and is not claimed).

F7. Scope. The theorem concerns polynomial degree over F only. It does not bound bit complexity,
circuit size, or sparsity of g, and does not exclude other representations of the discrete log
(rational functions, functions of (x, y), non-polynomial algorithms).

### Significance and novelty (plain)

Theorem C says: if a polynomial in the x-coordinate alone recovers the discrete log k from x(kP) on the
first N multiples, its degree must be at least about N/3, so for N ≈ r/2 at least about r/6. That is a
true but weak statement for ECDLP: degree is not running time, and a degree-r/6 polynomial says nothing
about whether some other algorithm (or a sparse/structured representation) computes logs quickly. Lower
bounds of this kind (degree, and also sparsity, of polynomials interpolating the elliptic-curve discrete
log from x-coordinates) appear, to my recollection, in earlier literature by Lange, Winterhof, Shparlinski
and co-authors around 2002–2005; I have not verified those sources or compared constants, so I would not
call Theorem C new. The main value here is the clean, machine-checked proof with explicit hypotheses
(char ≠ 2 only, no discriminant condition, no 3 ≠ 0) that reuses the Theorem B machinery.
